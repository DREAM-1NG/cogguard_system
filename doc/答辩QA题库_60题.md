### 编号：A1
**优先级：** P0
**专家类型：** 大同行
**模块：** 协同检测
**问题：** 请用一句话定义你们要解决的"协同行为检测"问题，并说明输入和输出分别是什么。
**15秒答案：** 在事件范围内，把多个账号围绕共享对象在相近时间窗口内的联动痕迹建模成多关系图，输出候选协同群组划分、账号级协同风险与机器人类别证据。
**40秒答案：** 输入是任务范围内采集到的多平台数据：账号集合、帖子/评论、共享对象（URL、Hashtag、媒体素材、转发/回复/提及目标等）及其时间戳。系统先把账号对在六类关系通道下的共现强度按公式 2-1 聚合，构成多关系协同图 G=(V,E,R)。输出分三层：①Leiden 划分出的候选协同群组 C={C1…Ck}，模块度最大化（公式 2-11）；②账号级 IO Driver 概率（公式 2-19/2-20），即"信息行动驱动账号"打分；③机器人类别 + 预测可靠性 + 纠错状态（公式 2-21~2-35）。这三层合起来就是"群组—成员—关系"三级协同证据。
**证据位置：** 申报书 2.2.3.1、2.2.3.1.1 公式 2-1~2-2；1.3.2
**可能追问1：** 你们的"协同"和普通的热门话题下用户自发聚集怎么区分？
**回答：** 自发聚集缺少"同一对象 + 相近时间窗口 + 多通道重复"这一组织化痕迹。我们用三重判据：共享对象共现的时间集中度（同步强度公式 2-38）、跨多类关系通道的共现（关系多样性熵 2-37）、以及时序上的突发性指标。自发共鸣通常只在单一通道（如纯转发）且时间分散，组织化协同在多个通道同时高度同步。这正是无监督方法假阳性高的根源，也是我们引入机器人检测和可靠性纠错做二次过滤的原因。
**可能追问2：** 那你们最终的"是否协同"判定是二分类还是排序？
**回答：** 不是单一二分类。社区检测环节对账号对输出边置信度（公式 2-8），可看做连续排序；Leiden 给离散群组划分；机器人检测给账号级概率。三者交叉后才形成"高协同群组"标记，回避了硬阈值问题。

### 编号：A2
**优先级：** P0
**专家类型：** 小同行
**模块：** 协同检测
**问题：** 你们说"覆盖六类协同行为通道"，具体是哪六类？为什么选这六类而不是更多或更少？
**15秒答案：** 六类是共享链接、媒体素材、话题与实体、互动目标（转发/回复/提及）、原生关系、近重复内容。选这六类是因为跨平台可观察、难规避、内容侧与行为侧互补。
**40秒答案：** 六类通道的划分有两个原则：①跨平台普遍存在——微博、小红书、抖音、X 都有 URL、Hashtag、媒体、互动对象这些结构，方法本身平台无关；②互补覆盖——URL/Hashtag/媒体偏内容侧，转发/回复/提及偏行为承接侧，原生关系（关注、好友等）偏平台结构侧，近重复内容（文本相似）覆盖没有显式共享对象但内容雷同的隐蔽协同。更少会漏掉某一侧的协同信号（例如纯文本复用型水军），更多则边际收益递减且噪声上升、元路径实例爆炸。
**证据位置：** 申报书 2.2.3.1 第 1 段、2.2.3.1.1 表 2-1
**可能追问1：** 表 2-1 只列了 5 条元路径（URL/Hashtag/Retweet/Reply/Mention），媒体素材和近重复内容这两类怎么没进元路径？【需补】
**回答：** 媒体素材和近重复内容没有作为独立的"账号—对象—账号"元路径列出，而是以两种方式进入：媒体素材走与 URL 相同的"账号—对象—账号"模板，对象类型扩展为媒体 hash；近重复内容不构造中继对象，而是作为边权——以文本相似度 s_ij 直接加权到融合图（公式 2-2 的 w_r 项）。所以六类通道齐全，只是其中两类不表现为独立元路径。【答辩前需确认实现代码里这两类的具体落地方式，以免被追问代码对不上】
**可能追问2：** 原生关系跨平台差异很大（微博关注 vs X follow），你怎么统一？
**回答：** 原生关系只用于补强已有协同边的权重，不单独驱动群组划分；跨平台时只取语义一致的子集（如互关、好友），平台特有的关系类型在采集映射阶段就归一掉了，避免平台间定义不一致。

### 编号：A3
**优先级：** P0
**专家类型：** 小同行
**模块：** 协同检测
**问题：** 公式 2-1 的"共现强度"是怎么算的？时间窗口设多长，时间衰减项是什么形式？
**15秒答案：** 共现强度 = 账号对在某关系下所有候选共现行为的时间衰减加权和；时间窗口按事件粒度可配置，衰减用指数核。
**40秒答案：** 对账号对 (u,v) 在关系 r 下，我们枚举它们在窗口 ΔT 内的所有候选共现行为 B_r(u,v)={(b, t_b, w_b)}，每条行为贡献一个时间衰减权重 exp(-|t_u - t_v|/τ_r)，再对相似度/共现权重 w_b 求和，得到 s_r(u,v, ΔT)（公式 2-1）。τ_r 是关系特定的时间尺度参数，转发类关系 τ 小（要求强同步），原生关系 τ 大（容忍慢扩散）。窗口 ΔT 不是全局固定值，而是按事件时长自适应——长事件按天切片做演化，短事件用小时窗。窗口大小通过验证集 NMI/Modularity 调优。
**证据位置：** 申报书 2.2.3.1.1 公式 2-1、2-2
**可能追问1：** τ_r 和 ΔT 的具体取值是多少？
**回答：** 【需补】申报书未列具体数值。答辩前需给出每类关系的 τ_r 和典型事件的 ΔT，并附敏感性曲线说明在 ±2× 范围内 NMI 波动小于 X%，证明不是精调出来的。
**可能追问2：** 不同事件的时间尺度差几个数量级，一个 τ 怎么通用？
**回答：** τ_r 是相对单位（归一化到事件时长），不是绝对秒数；而且我们还在三个时间尺度上分别生成群组集合（公式 2-40）做演化追踪，相当于多尺度覆盖，单一 τ 的不适配由演化证据弥补。

### 编号：A4
**优先级：** P0
**专家类型：** 小同行
**模块：** 协同检测
**问题：** 为什么选 MAGNN？HAN、RGCN、HGT 这些异构图方法为什么不行？
**15秒答案：** 协同图是"账号—共享对象—账号"的天然异构中继结构，MAGNN 显式聚合元路径实例，比 HAN 的节点级平均、RGCN 的关系变换更贴合"两个账号共享同一对象"这一协同语义。
**40秒答案：** 四种方法都能处理异构图，但建模假设不同：RGCN 按关系类型做消息变换，不显式建模"中继对象"，协同证据（共享的具体 URL/Hashtag）会被压进边权丢失；HAN 虽然也用元路径 + 两级注意力，但它对同一元路径的所有实例先平均再聚合，抹平了"同一对象上不同实例的判别力差异"；HGT 用 Transformer 做关系/类型注意力，表达力强但需大规模监督且对稀疏协同图过拟合。MAGNN 的关键区别是：先对每条元路径实例编码（公式 2-3），再做实例级注意力（2-4/2-5），再做语义级注意力（2-6/2-7），保留"哪条共享对象更可疑"的实例级信号，最后用无监督边重构训练（2-8/2-9），不需要节点标签——契合协同检测标注稀缺的现实。
**证据位置：** 申报书 2.2.3.1.1 公式 2-3~2-9；参考文献 [45] MAGNN
**可能追问1：** MAGNN 原论文是监督任务，你们改成无监督边重构，和原论文的区别在哪？
**回答：** 原论文 MAGNN 在有节点标签的节点分类/聚类上端到端训练。我们去掉分类头，保留元路径实例编码 + 两级注意力作为编码器，以观测协同边为正样本、未连接对为负样本做链路重构（2-8/2-9），学到的边置信度再反向加权融合图（2-10）。这是把 MAGNN 当无监督表示学习器用，输出供 Leiden 划分，而非原论文的端到端分类。
**可能追问2：** 负采样怎么做？正负极度不平衡怎么处理？
**回答：** 负样本按度分布加权随机采样未连接对，正负比约 1:5~1:10；loss 用带正类权重的交叉熵（2-9），并对高频账号降权避免热门账号主导。

### 编号：A5
**优先级：** P0
**专家类型：** 小同行
**模块：** 协同检测
**问题：** MAGNN 的两级注意力——实例级和语义级——分别在算什么？消融掉哪一级影响大？
**15秒答案：** 实例级注意力聚合"指向同一账号的多条元路径实例"，语义级注意力融合"不同关系通道"。消融上实例级影响更大，因为它直接决定"哪个共享对象更可疑"。
**40秒答案：** 第一级实例级注意力（公式 2-4/2-5）：对同一账号 u 在关系 r 下收到的所有元路径实例（即 u 通过不同共享对象与各邻居形成的路径），学一组注意力权重 α，加权求和得到 u 在关系 r 下的表示 h_u^r。这一级回答"同一关系里，哪条共享对象上的共现更可信"。第二级语义级注意力（2-6/2-7）：对不同关系通道 r 的表示 h_u^r 再学一组注意力 β，加权融合得到最终节点嵌入 h_u。这一级回答"在当前事件里，哪类关系更有判别力"。两级串联使模型能事件自适应地给不同通道不同权重，而不是全局固定权重。消融：去实例级（退化为实例平均，近似 HAN）下降最大；去语义级（各关系等权）下降次之；两级都去退化为单关系 GNN，下降最明显。【需补：申报书测试小结提到消融但未给数字表，答辩前必须补具体数字】

**回答：** 【需补】这是高风险点。答辩前必须补一张消融表，至少四行：完整模型、去实例注意力、去语义注意力、去边重加权，报 Macro-F1/AUC/AUPRC。若来不及跑全六国数据集，至少在两个代表数据集（如中国 + 俄罗斯）上跑。没有这张表，这句话在答辩里站不住。

### 编号：A6
**优先级：** P0
**专家类型：** 小同行
**模块：** 协同检测
**问题：** 边重加权（公式 2-10）把 MAGNN 学到的边置信度反作用回融合图，这个 α 混合系数怎么定？会不会让模型自嗨？
**15秒答案：** α 控制统计共现权重和模型学到的边置信度的混合比例，用验证集模块度/NMI 网格搜索确定，不是手调。模型自嗨风险由"边重构 + 原始统计双输入"约束。
**40秒答案：** 公式 2-10 的边重加权写成 w'_ij = (1-α)·s_ij + α·p_ij，s_ij 是原始协同行为统计（公式 2-1/2-2），p_ij 是 MAGNN 边重构概率（2-8）。α 在 [0,1] 上以验证集 Modularity 和 Seed NMI 为目标做网格搜索，取拐点。模型自嗨（即 MAGNN 把噪声边也学成高置信）的风险由两点抑制：①p_ij 的训练信号本身来自 s_ij 构成的正样本，二者不会完全背离；②α 不取 1，原始统计始终保留一份基线权重，等于给模型加了正则。极端情况下若 MAGNN 学坏，α 退化为 0 即可回到纯统计基线，系统不会比无模型更差。这也是消融里"去边重加权"那一行的作用。
**证据位置：** 申报书 2.2.3.1.1 公式 2-8、2-10
**可能追问1：** α 在不同数据集上是不是差很多？如果每个数据集单独调 α，是不是过拟合？
**回答：** 【需补】α 的跨数据集取值需答辩前给出。正确做法是：在验证子集上调 α，在测试集固定使用，且报告"α=0/0.5/1 三个固定值"的结果作为鲁棒性证据，证明不是逐数据集精调。
**可能追问2：** 模块度本身有分辨率参数 γ 偏好，用它调 α 会不会循环论证？
**回答：** γ 和 α 分两层调优、用不同目标：α 用 Seed NMI（与真实标签的一致性），γ 用 Modularity（结构质量）。Seed NMI 是外部指标，不参与 γ 的结构优化，避免循环。

### 编号：A7
**优先级：** P0
**专家类型：** 小同行
**模块：** 协同检测
**问题：** 为什么用 Leiden 而不是 Louvain？分辨率参数 γ 是什么，怎么选？
**15秒答案：** Leiden 比 Louvain 多了社区细化阶段，保证社区内部连通，避免 Louvain 著名的"badly connected community"问题；γ 控制社区粒度，偏大社区更小更密，偏小社区更大更松，按验证集 NMI 选。
**40秒答案：** Louvain 只做节点局部移动 + 网络聚合两阶段，已证明会产出内部不连通的社区（Traag et al. 2019）。协同检测里一个群组必须是结构上连通的协同单元，不连通的社区在证据展示时无法解释（群组成员之间没有联动路径），所以必须用 Leiden。Leiden 三阶段：节点局部移动（贪心提升模块度）→ 社区细化（把松散社区拆成连通子社区）→ 网络聚合（超节点重复），公式 2-11 的模块度 Q = Σ[Σ_in/(2m) - (Σ_tot/(2m))²]^γ，γ 是分辨率参数。γ<1 倾向大社区、γ>1 倾向小社区。γ 在验证集上以 Seed NMI 为目标搜索，典型取值在 1.0~1.5。
**证据位置：** 申报书 2.2.3.1.1 公式 2-11、2-12；参考文献 [21]
**可能追问1：** 协同群组规模不均衡，Leiden 怎么应对？
**回答：** Leiden 的细化阶段天然处理这个问题：大而松的社区会被拆分成连通子社区，小而密的社区保留。我们还在评估时同时报 Modularity 和 Density（公式 2-36），分别看结构质量和内部紧密度，避免单一指标偏向大社区。
**可能追问2：** Leiden 是启发式的，每次跑结果不一样，你怎么保证可复现？
**回答：** 固定随机种子；且 Leiden 在模块度收敛后划分趋于稳定，我们报多次运行均值±标准差。线上推理时同一事件快照下结果是确定的（同一输入同一图）。

**40秒答案：** BotRHG 的核心动机是计算效率和纠错质量的双目标。流程：①基础检测器用账号文本+属性+多关系图给出初始后验 p̂（公式 2-21/2-22）；②算置信缺口 = 最大类概率 - 次大类概率（2-23），缺口小 = 模型不确定；③在融合表示空间找 k 近邻，算局部预测可靠性（2-26，近邻预测一致性）和纠错风险（2-27）；④给定纠错预算 m，只选纠错风险最高的 m 个账号（2-28/2-29）；⑤对这 m 个账号用近邻构建目标中心超边（2-30），超图传播得高阶表示（2-31），残差注入（2-32~2-34）；⑥选择性纠错规则（2-35）：高可靠账号用基础预测，低可靠账号用纠错后预测。不全上超图的原因：①超图传播计算 O(m·k)，全量账号上线性不可行；②高可靠账号本身预测就对，强行用邻居纠错反而被邻居噪声带偏，实测会掉点。这是"把昂贵计算花在边界样本上"的思路。

### 编号：B1

问题： 你们的传播预测到底预测什么？输入是什么，输出是什么？
15秒答案： 输入是事件早期已观测到的传播级联前缀（谁在何时参与了传播）+ 账号关系图，输出是三件事：最终传播规模、未来累计增长趋势曲线、潜在后续参与账号排序。
40秒答案： 对一个事件的一条级联 c，在观测时刻 t_obs 前已参与的账号按时间序记为 S={a_1(t_1),…,a_{n_obs}(t_{n_obs})}（公式 2-43）。模型只用 S 中已发生行为建状态，t_obs 之后的行为是预测目标。输出三元组（公式 2-78）：①规模 R̂——事件最终传播账号数；②趋势 {T̂_1…T̂_N}——N 个未来检查点的累计传播规模轨迹；③下一跳 L——Top-K 潜在后续参与账号排序。三件事对应宏观、时序、微观三个尺度，互为补充：规模说最终多大，趋势说怎么长过去的，下一跳说下一个谁接力。这是与单做规模预测（MINDS 宏观）或单做下一跳（FOREST 微观）的区别。
证据位置： 申报书 2.2.3.2.1 公式 2-43；2.2.3.2.3 公式 2-78
可能追问1： 三个输出是一次前向一起出，还是分阶段？
回答： 一次前向。共享传播状态 h（公式 2-53）一次性算出，宏观头出规模+趋势，微观头出下一跳，单次编码多任务解码。趋势解码虽是 Euler 多步展开，但在训练和推理里都是一次前向的循环展开，不调用外部模型。
可能追问2： 最终传播规模的最终指多久之后？事件不会无限传播。
回答： 最终指传播基本饱和后的累计规模，工程上以连续 X 天无新增为收敛判据定义终点。不同事件收敛时长不一，我们对每个级联用其历史收敛点做标签。

### 编号：B2
优先级： P0

问题： RelationGNN 在你们模型里干什么？为什么需要它，光有传播序列不够吗？
15秒答案： RelationGNN 聚合参与账号及其关系邻居，给序列里每个账号注入它周围是谁的关系上下文，弥补纯时序模型看不到关系结构的缺陷。
40秒答案： 纯 LSTM 只看谁在何时参与，看不到这个账号的关注网络里还有谁、谁和它同群。但传播接力高度依赖关系结构——下一跳往往在已参与账号的关系邻居里。RelationGNN 对序列中账号 a 的关系邻居集 N(a) 做平均聚合（公式 2-45），再与账号自身表示拼接过非线性映射（2-46），得账号关系特征；再对序列所有账号的关系特征聚合形成事件级关系上下文 c_rel（2-47）。这个 c_rel 进入共享状态（2-53），使后续预测既知道传播序列长什么样，又知道参与账号的关系环境长什么样。本质是把传播发生在关系网络之上这个先验显式编码进去。
证据位置： 申报书 2.2.3.2.1 公式 2-45~2-47
可能追问1： RelationGNN 用的什么图？和协同检测的图是同一张吗？

问题： Shared LSTM 为什么叫"Shared"？共享的是参数还是表示？它和宏微观两个任务的关系？
15秒答案： 共享的是表示——同一个 LSTM 同时编码序列状态供宏微观两个任务头用，让两个尺度在共享传播状态 h（2-53）上互相约束。
40秒答案： Shared LSTM 的输入是序列中第 i 个账号的时序表示 x_i（公式 2-52）= 用户嵌入 + 关系上下文 c_rel + 时间特征 t_i。它依次读取传播序列，通过输入门/遗忘门/输出门累积传播历史，输出隐藏状态序列。关键设计：①共享——宏微观两个任务不各跑一个 LSTM，而是共用这一个时序编码器，因为整体规模规律和局部接力规律共享同一套传播历史记忆，分开学会重复且互相冲突；②融合——LSTM 隐藏态再与关系上下文 c_rel、级联上下文 c_cas、当前观测规模 n_obs、观测比例 ρ_obs 融合成核心共享状态 h（公式 2-53）；③任务专有映射——h 之后才分叉出 h_macro 和 h_micro（2-54），共享表示保公共规律，专有头强化各自关注。这是 MINDS 多尺度共享表示思想的延续，我们的增量在 h 之后加了 GRL 和趋势解码。
证据位置： 申报书 2.2.3.2.1 公式 2-52~2-54
可能追问1： 共享 LSTM 会不会让两个任务互相干扰（负迁移）？
回答： 有这个风险，特别是规模差异大的级联。缓解：①GRL 阶段对抗分支（2-55/2-56）让 h 对观测阶段不敏感，减少单尺度偏差；②任务专有映射 h_macro/h_micro 分支后各自有独立参数，共享只到 h 层；③loss 权重可调，若某任务长期拖累可降权。若实测负迁移严重，退化为双 LSTM 是 fallback。
可能追问2： 为什么用 LSTM 不用 Transformer？
回答： 传播序列是有严格时序的递进结构，LSTM 的门控天然适合累积型状态（规模只增不减）。Transformer 的全局注意力在短序列上优势不明显，且位置编码对时间间隔的建模不如 LSTM 直接。工程上 LSTM 也更轻。

40秒答案： h 是整个联合模型的核心，它要把分散的传播证据映射到统一表示空间。五成分：①LSTM 隐藏态——时序记忆，回答传播过程走到哪了；②c_rel（2-47）——关系环境，回答参与账号的关系网络长什么样；③c_cas（2-51）——级联结构，回答当前是哪些账号一起扩散；④n_obs——当前已观测规模，绝对量级信号；⑤ρ_obs = n_obs / n_final（近似）——观测完整度，阶段信号。后两个是显式数值特征，让模型知道现在处于早期还是中后期。设计逻辑：宏微观任务都需要这五类信息，但侧重点不同（宏观看规模和阶段，微观看关系和级联），所以共享 h 再分叉。h 之后还有 GRL 分支（2-55）做阶段对抗，让 h 不被某一观测阶段主导。

### 编号：B6

问题： GRL（梯度反转层，公式 2-55/2-56）在你们模型里干什么？λ 怎么调？
15秒答案： GRL 让共享状态 h 对"观测阶段"不可分，防止模型过拟合到某一阶段（如只擅长早期），提升跨阶段泛化。λ 是对抗权重，从 0 暖升到大值。
40秒答案： 传播预测有个隐患：训练数据里早期级联和晚期级联分布不同，模型可能学到"看到长序列就预测大、短序列就预测小"的阶段捷径。GRL 解决：接一个阶段判别器（2-56）预测当前样本处于哪个观测阶段，前向保持 h 不变，反向通过梯度反转（2-55，前向 x、反向 -λx）让 h 的更新方向与判别器相反——判别器想区分阶段，编码器就让 h 越来越不分阶段。结果是 h 对阶段鲁棒，不同观测完整度下的样本映射到稳定公共空间。λ 调度：训练初期 λ=0（先学好主任务），随 epoch 线性/指数升到 λ_max（逐步加对抗强度），避免一开始对抗太强训不动。λ_max 在验证集调，过大主任务掉点，过小无对抗效果。
证据位置： 申报书 2.2.3.2.1 公式 2-55、2-56
可能追问1： GRL 是 DANN 的经典技巧，你们和 DANN 的区别？
回答： 思想同源（域对抗）。我们的"域"是观测阶段而非数据集域，且 GRL 只作用于共享 h，不作用于任务专有头 h_macro/h_micro。这是把 DANN 用作正则而非主任务。
可能追问2： 阶段判别器的标签怎么定义？
回答： 按观测比例 ρ_obs 分桶（如早/中/晚三档）作离散标签。也可连续回归，但分类更稳。

问题： 宏观规模预测为什么在对数空间做？为什么预测"增长量"而非"最终规模"？Softplus 起什么作用？
15秒答案： 对数空间压长尾；预测增量让大小级联训练信号归一；Softplus 保证增长量非负，最终规模只增不减。
40秒答案： 三点动机：①对数空间（公式 2-57，log n_obs）——传播规模跨数量级（几十到几十万），直接预测小级联被大级联的梯度淹没，log 压到相近量级；②预测增量 Δ（2-58，h_macro → Softplus → ΔR̂）而非绝对最终规模——预测"从当前还要涨多少"比"最终多大"更归一化，因为不同起点的级联增量可比；③Softplus 保证 ΔR̂>0——传播规模物理上单调不减，Softplus（Softplus(x)=log(1+e^x)）恒正，强制模型输出非负增长量，避免预测出"规模倒退"的荒谬结果。最终规模 R̂ = n_obs + exp(ΔR̂)（2-59/2-60，在对数空间还原）。这套设计让预测既数值稳定又满足单调性约束。
证据位置： 申报书 2.2.3.2.2 公式 2-57~2-60
可能追问1： log 空间还原回真实规模时有偏（Jensen 不等式），怎么处理？
回答： 有偏。我们在验证集上估一个校正系数修正系统偏差，或直接在 log 空间评估（MSLE 指标本身就是 log 空间，见 B13）。报告 MSLE 和 MAE 两个口径，让评估方自己判断。
可能追问2： 预测增量依赖 n_obs 准确，n_obs 缺数据时怎么办？
回答： n_obs 来自采集的传播序列长度，缺数据时 ρ_obs 也失真，此时模型置信度低，会在难例筛选环节被标为需复核。不在传播模块内强行补 n_obs。

### 编号：B9
优先级： P0
专家类型： 小同行

问题： 连续趋势预测用显式 Euler 方法（公式 2-69/2-70）解码，为什么不用 RK4 或直接用网络回归多个点？Euler 误差不更大吗？
15秒答案： Euler 简单可微、步长可控、能自然保证单调累计；RK4 计算翻 4 倍收益小，且不自带单调性；直接回归多点会丢失时序依赖。
40秒答案： 趋势解码把"未来增长"建模成潜在状态 z 随时间 t 连续演化的动态方程 dz/dt = f_θ(z, t)，用可训练网络 f_θ 学这个动态。离散积分用显式 Euler：z_{k+1} = z_k + Δt·f_θ(z_k, t_k)（2-69/2-70）。选 Euler 的理由：①简单可微——Euler 一步就是线性加法，梯度沿时间步自然反向传播，训练稳定；②步长可控——Δt 按检查点数 N 归一化，N 越大越准，可按算力调；③单调性——配合 Softplus 输出非负增量（2-71），Euler 累加天然保证累计规模只增不减（2-75）；④和 CasFT 的区别——CasFT 侧重趋势建模思想，我们把它落到高维潜在空间的动态方程，比 CasFT 在统计量上外推更结构化。RK4 精度高 4 倍算力，且不自带单调约束需额外正则；直接回归 {T̂_1…T̂_N} 各点独立会丢时序依赖、不保证单调。Euler 是精度/效率/约束的最佳折中。
证据位置： 申报书 2.2.3.2.3 公式 2-69~2-71、2-75
可能追问1： Euler 在刚性系统（快变）上不稳定，传播尖峰怎么办？
回答： 传播尖峰由 Softplus 增量 + 注意力超边捕捉，潜在动态方程 z 是平滑的高维状态，不在 z 上直接拟合尖峰数值。Euler 积分的是平滑 z，输出增量再映射回规模。步长 Δt 可在尖峰期加密。
可能追问2： f_θ 是什么网络？多深？
回答： 轻量 MLP（2~3 层），输入 (z_k, t_k, ρ_obs)，输出 dz。深了过拟合且算力高，浅了表达力不够，2~3 层是验证集调的。

问题： 你们怎么保证预测的趋势曲线单调非递减？万一中间检查点比最终规模还大呢？
15秒答案： 两道约束：①每步增量用 Softplus 强制非负（2-71），累计自然单调（2-75）；②最终规模 = max(独立头预测, 趋势终点)（2-76），保证最终不小于趋势累计。
40秒答案： 单调性是传播规模的物理约束——累计参与账号数不会随时间倒退。两道约束：第一道，趋势每步增量 ΔT̂_k = Softplus(g(z_k))（2-71），Softplus 恒正，所以累计 T̂_k = Σ ΔT̂_j 只增不减（2-72/2-75），这是过程级约束；第二道，独立宏观头预测的最终规模 R̂_ind 和趋势最后一个检查点 T̂_N 可能不一致（两个预测路径），取 max（2-76）作为最终规模 R̂_final，保证最终规模 ≥ 趋势已累计到的值（2-77），这是结果级一致性约束。这样无论模型怎么训，输出都不会出现"中间点规模 > 最终规模"的矛盾。这是 CasFT 思想的严格化——CasFT 提出趋势建模，我们用 Softplus+Euler+max 把单调性变成可证明的硬约束。
证据位置： 申报书 2.2.3.2.3 公式 2-71、2-75、2-76、2-77
可能追问1： max 约束会不会让最终规模系统性偏大？
回答： 会有上偏。但传播规模的下游用途是风险研判（判断事件是否严重），上偏比下偏安全——漏报严重事件代价更大。且我们在 log 空间评估，偏差被压缩。若需无偏可改用加权平均，但牺牲一致性保证。
可能追问2： Softplus 恒正但接近 0 时梯度也小，训练会不会卡？
回答： Softplus 在 x 大时梯度正常，x 很负时梯度接近 0（对应"几乎不增长"的样本），这恰好是我们想要的——对真不增长的样本少更新。没有卡死问题。

### 编号：C1

问题： 你们为什么搞分层架构？轻量模型 + 多智能体两套，不能只用一套吗？
15秒答案： 轻量模型快但浅，多智能体深但慢。分层把昂贵深度分析只花在难例上，成本近似线性而非全量 LLM 调用，公式 2-106/2-107 给了成本对比。
40秒答案： 动机是深度与效率的矛盾。若全量走多智能体：N 个分析对象每个都要多轮 LLM 调用 + 检索 + 反思，成本 ≈ N·c_deep（公式 2-107），线上不可行。若只用轻量模型：单次编码分类，快但无法主动检索外部证据、无法多步推理，对复杂事件判断浅。分层解法（2-106）：N 个对象先过轻量模型（成本 N·c_light，单次编码+任务头），按不确定性/证据冲突/OOD 排序筛出 m 个难例（m << N），只对这 m 个走多智能体深度研判，其中 k 个再生成反制措施。总成本 ≈ N·c_light + m·c_deep + k·c_counter << N·c_deep。关键是难例筛选让深度资源集中。这是工程上把 LLM 当"昂贵的专家咨询"而非"通用分类器"的思路，也是 MARO/PGKD 等工作的共识。
证据位置： 申报书 2.2.3.3、2.2.3.3.4 公式 2-106、2-107
可能追问1： m 和 k 各占 N 多少？
回答： m 典型占 5%~15%（按难例排序阈值切），k 占 m 的子集（确认高风险的）。具体比例按 c_light/c_deep 的成本比和预算调——若 LLM 成本高则 m 小。线上可动态：先跑前 10% 看效果再扩。
可能追问2： 分层会不会漏掉难例（轻量模型把难例误判为易）？
回答： 这是风险。缓解：难例筛选不只看模型置信度，还看证据冲突和 OOD（公式 2-83），这两项能抓到"模型自信但证据矛盾"的隐蔽难例。且保留人工复核队列兜底。但承认这是分层的固有代价。

15秒答案： 三个实质区别：①决策规则离线优化（MARO 是固定 prompt）；②RAG 证据字段独立可追溯（MARO 不强调）；③知识蒸馏 + DAPT 把深度能力迁移到轻量模型（MARO 无此环节）。
40秒答案： 必须讲清与 MARO（参考文献 [35]）的差异，否则被批"换皮"。三点实质创新：①决策规则——MARO 的 Judge 用固定人工提示规则聚合，依赖专家经验；我们做离线规则优化（C8，公式 2-94~2-97），基于跨域验证任务集数据驱动学规则，可跨域可持续优化。这是最核心区别。②证据表示——MARO 各专家产出报告但不强调证据字段结构化；我们 RAG 把 claim/query/source/quoted span/retrieval status/evidence relation 拆成独立可追溯字段（C5，公式 2-87），支持逐条复核和防幻觉，且明确把"有无声明/检索成败/证据是否支持"独立化。③能力沉淀——MARO 是纯在线多智能体，每次都跑全流程；我们通过知识蒸馏（C9）+ DAPT（C10）把深度研判的高质量结果迁移到轻量模型，使大部分内容在线用轻量模型处理，只难例走深度。这是分层架构 MARO 没有的。共同点（承认）：多专家分工 + 问题反思迭代机制确实沿用 MARO 思想，申报书明确引用其消融结论（移除 Questioning Agent 性能下降）作为反思有效性依据。
证据位置： 申报书 2.2.3.3.2~2.2.3.3.5；参考文献 [35] MARO
可能追问1： 那反思机制你们和 MARO 完全一样？
回答： 机制思想同源（初轮→反思→补充），但我们的反思 Agent 检查维度扩展到协同/传播上游证据（不止内容），且反思结果可作为蒸馏数据回流（MARO 无）。结构性改进有限，我们诚实承认反思机制是沿用。
可能追问2： 规则优化比 MARO 固定 prompt 好多少？有对比吗？【需补】
回答： 【需补】应做 MARO（固定 prompt）vs 我们（离线优化规则）的对比，在相同验证集上报 Accuracy/Macro-F1。这是证明核心创新有效的关键实验，当前无。答辩前必须补，否则"区别"只是设计层面无效果证据。

### 编号：C17
优先级： P1
专家类型： 工程
模块： 风险研判
问题： 多智能体用的什么 LLM？线上延迟和成本多少？能承受吗？
15秒答案： 底座是某开源大模型（如 Qwen/LLaMA 系列），单次深度研判含多轮 LLM 调用 + 检索，延迟分钟级，只对难例跑（m << N）所以总成本可控。
40秒答案： LLM 选型【需补：申报书未指明具体模型，答辩前必须明确——开源（Qwen/LLaMA/GLM）还是闭源 API，规模多大】。延迟构成：①声明抽取 + 查询生成——1 次 LLM 调用；②RAG 检索——向量检索秒级；③各专家初轮——K 个 Agent 各 1 次（K≈3~5）；④反思——1~2 轮，每轮再 K 次；⑤Judge——1 次。总计约 10~20 次 LLM 调用，开源 7B 模型单次秒级，总延迟分钟级。成本：开源自部署只算 GPU，闭源 API 按调用计费。可承受性靠分层——只 m 个难例走，若 m=5%N、N=10000，则 500 次深度研判，分钟级延迟可离线批处理或异步返回。线上实时性要求高的用轻量模型，深度研判异步。部署：测试在 RTX 4060（8GB 显存跑不了大 LLM），生产需更大显存 GPU（如 A100 或 API）。
证据位置： 申报书 2.2.3.3、3.4.1；需补 LLM 选型
可能追问1： 开源 7B 够用吗？推理质量比闭源差多少？
回答： 【需补】应在验证集上对比 7B 开源 vs 闭源 API（如 GPT-4 级）的研判质量，若 7B 达到 API 的 90% 且成本低 10 倍，则选开源。当前无对比。
可能追问2： 多次 LLM 调用怎么保证一致性？
回答： 温度设低（T=0~0.3）减随机性；关键判断（Judge）多候选投票；结构化输出约束格式。完全一致不可能，但通过规则优化（C8）让 Judge 对专家间分歧有鲁棒聚合规则。
