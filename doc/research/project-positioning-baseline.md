# 项目统一口径与修订基线

> **用途**：沉淀项目问题对象、统一叙事、旧表述纠偏和三项关键技术定义。  
> **受众**：研究撰写者、竞赛材料撰写者、系统设计维护者。  
> **维护规则**：只维护研究和叙事口径；工程状态、任务优先级和运行说明放入 `../engineering/`。

本文档作为当前项目的单一口径基线，供开题报告、答辩 PPT、系统设计说明、任务拆分与后续实现统一使用。

## 1. 项目统一定义

### 1.1 项目名称

面向网络舆论对抗的跨平台协同攻击监测系统

### 1.2 不再采用的旧表述

以下表述不再作为项目 headline、主功能概括或关键技术总括：

- 话题监测 + 机器人检测 + 意图识别
- 舆情分析 + bot 检测 + 报告生成
- 多模态异构图 + Agent + DISARM

原因如下：

- 这些表述偏“方法驱动”，不能准确体现项目要解决的问题对象。
- 容易退回到“社交机器人集群检测及意图识别”的旧任务骨架。
- Agent 与 DISARM 在本项目中是支撑层，不是三项关键技术本体。

### 1.3 当前统一的问题对象

本项目的核心对象是跨平台协同攻击行为。

系统围绕三大主要功能形成闭环，每个功能下包含多个子功能，技术是对功能的支撑，按重要程度分为关键技术和其它技术。



#### 功能一：协同发现

发现跨平台协同行为，并对协同行为进行分类。

| 层级 | 内容 |
|------|------|
| **子功能** | 协同行为检测、协同类型分类、协同群组发现、证据边提取 |
| **关键技术** | 基于多任务框架的协同检测（是否**协同二分类** → 协同类型分类），参考 2024 Coordination Detection Toolkit |
| **其它技术** | 后期动态调整（候选：多行为边构建、显著性筛查、社区发现等） |



系统功能：多模态展示 - 返回  演示规模  性能提示 



#### 功能二：传播监控

对传播源头、范围和趋势进行监控与预测。

| 层级 | 内容 |
|------|------|
| **子功能** | 趋势预测、用户画像、立场检测、危害性评估、源头追溯、范围估计 |
| **关键技术** | LLM + 时序预测（**趋势预测**） |
| **其它技术** | 后期动态调整（候选：图分析、角色识别、立场分类模型等） |



#### 功能三：报告研判

针对攻击进行分析并生成报告，显式利用前两个功能所生成的结果。

| 层级 | 内容 |
|------|------|
| **子功能** | 攻击分析、报告生成、DISARM 映射、处置建议、预警 |
| **关键技术** | Agent + RAG（攻击分析与报告生成） |
| **其它技术** | 后期动态调整（候选：知识库构建、模板引擎、结构化输出等） |



### 1.4 与旧框架的边界

与“群体分析 - 机器人画像 - 意图识别”的旧主轴相比，当前项目的区别在于：

- 研究对象从单账号/账号群体转为跨平台协同操纵网络。
- 主流程从账号分类转为证据驱动的发现、归因与报告研判闭环。
- 输出从 bot/human 或意图标签转为事件、群体、路径、claim、thread 多层风险与证据链。

## 2. 推荐主流程

### 2.1 三大功能闭环

系统的三阶段是三种主要功能的闭环：

```
协同发现 ──→ 传播监控 ──→ 报告研判
   │                          │
   └──────────────────────────┘
```

每个功能独立提供价值，同时为下游功能提供输入。

### 2.2 功能、子功能与技术的关系

```
功能（三大主要功能，构成闭环）
  └── 子功能（每个功能下的具体能力）
        └── 技术（支撑子功能的实现手段）
              ├── 关键技术（核心创新点，每个功能一项，已确定）
              └── 其它技术（支撑性技术，后期动态调整）
```

**关键技术是从功能中提炼出的核心创新点，不等同于功能本身。**

### 2.3 各功能子功能清单

**协同发现**：
- 协同行为检测（是否存在协同）
- 协同类型分类（什么类型的协同）
- 协同群组发现（哪些账号构成协同群体）
- 证据边提取（协同行为的证据链）

**传播监控**：
- 趋势预测（传播量/范围/速度的未来走势）
- 用户画像（角色识别与行为特征）
- 立场检测（支持/反对/中立/讽刺）
- 危害性评估
- 源头追溯（传播起点定位）
- 范围估计（传播覆盖面）

**报告研判**：
- 攻击分析（基于多源证据的深度分析）
- 报告生成（结构化攻击分析报告）
- DISARM 映射（战术/技术标准化表达）
- 处置建议（基于分析结果的行动建议）
- 预警（风险等级与告警）

## 3. 系统模块边界

### 3.1 任务编排与监测策略配置

作用：
定义监测任务，而不只是配置参数。

任务模式：

- 事件驱动：给定热点话题、实体、关键词、时间窗。
- 对象驱动：给定可疑账号、组织、媒体源、传播对象。
- 混合驱动：事件与对象联合。

输出：

- 目标平台
- 时间范围
- 事件种子
- 风险阈值
- 预警规则
- 证据保留级别

### 3.2 事件触发与跨平台采集

作用：
围绕事件单元构建原始证据池，而不是全网盲爬。

采集对象：

- 原帖
- 评论 / 回复
- 转发关系
- 账号元数据
- 外链
- 图片 / 视频指纹
- 时间戳
- 互动计数

原则：

- 不强求跨平台强身份统一。
- 围绕事件窗口做增量采集。
- 以事件为采集单位，不以平台为单位。

### 3.3 跨平台证据标准化与对齐

作用：
这是当前系统与旧式“先做 bot 再拼群体”流程拉开差距的第一个关键模块。

对齐层次：

1. 事件对齐：不同平台上的同一事件聚合到同一事件簇。
2. claim 对齐：同一口径、同一断言、同一素材模板聚成 claim 簇。
3. 软账号关联：不做强 identity resolution，而是建立行为、内容、时间、资源层面的软连接。

关键数据实体：

- Event
- Claim
- Thread
- Account
- Resource
- Platform
- Time bucket

### 3.4 协同发现

作用：
主闭环中的第一个核心模块。发现跨平台协同行为并进行分类。

当前定义：
定位为多任务问题，基于 2024 年 Coordination Detection Toolkit：
- **任务一（二分类）**：给定一组行为对，判断是否存在协同（coordinated vs organic）
- **任务二（类型分类）**：对已识别的协同行为进行类型分类（astroturfing / brigading / amplification / ...）

处理步骤：

- 多行为协同边构建（五类边：时间同步、共链接、共媒体、语义近似、传播互动）
- 显著性筛查（统计检验区分自然共振与人为协同）
- 候选协同对/群体发现
- 协同类型分类

输出：

- 协同/非协同判定结果
- 协同类型标签
- 可疑协同群体
- 关键协调证据边
- 核心共享资源

### 3.5 传播监控与趋势预测

作用：
主闭环中的第二个核心模块。对传播源头、范围和趋势进行监控与预测。

核心思想：
不再只输出”谁传播了什么”，而是预测”传播趋势会如何发展”。关键技术为 LLM + 时序预测。

子功能：

- 用户画像与角色识别（起爆/桥接/扩散/伪装意见领袖）
- 立场检测（支持/反对/中立/讽刺）
- 危害性评估
- 源头追溯与范围估计
- **趋势预测**（LLM 增强的时序预测模型）← 关键技术

输出：

- 传播趋势预测（未来 N 小时传播量/范围/速度）
- 用户画像与角色标签
- 立场分布与演化
- 危害性评分
- 源头追溯结果
- 传播范围估计

### 3.6 账号自动化先验与角色画像

作用：
支撑传播监控，而非最终裁决。

输出特征：

- 自动化概率
- 行为模板化程度
- 发文节律异常
- 交互规律性
- 历史参与模式

原则：
账号层承担角色画像和证据增强，不承担最终 bot/human 二元判定。

### 3.7 报告研判与攻击分析报告

作用：
主闭环中的第三个核心模块。针对攻击进行分析并生成报告。

核心思想：
旧有的报告生成和风险模块通常作为分类的可解释性支撑，但在本项目中，我们使用 Agent + RAG，显式利用协同发现和传播监控所生成的结果，进行深度攻击分析。

核心方法：

- **Agent 编排**：消费 KT1 协同发现结果（协同群组、类型分类）和 KT2 传播监控结果（趋势预测、用户画像、立场、危害性）
- **RAG 检索**：从 DISARM 知识库、历史案例库、外部证据库中检索相关信息
- **攻击分析**：基于多源证据进行结构化攻击分析
- **报告生成**：生成可审计的攻击分析报告

输出：

- 攻击分析报告（结构化 JSON + 自然语言）
- DISARM 战术/技术映射
- 处置建议
- 风险预警

### 3.8 DISARM 战术映射与可审计报告生成

作用：
处置支撑层，不是核心检测层。

准确定义：
证据编排、战术映射与可审计报告生成。

报告内容：

- 事件概览
- 关键 claim
- 协同群体
- 关键传播角色
- 主要证据链
- DISARM tactic / technique 映射
- 处置建议

约束：

- DISARM 是知识框架，不是检测算法。
- Agent 是 orchestration / synthesis 层，不是三项关键技术之一。

### 3.9 风险预警、案例入库与处置支撑

输出级别：

- 事件级告警
- 群体级告警
- claim / thread 级告警

扩展功能：

- 案例回写
- 相似案例检索
- 人机复核支撑
- 规则更新依据

## 4. 三项关键技术

> 关键技术是从三大功能中提炼出的核心创新点，每个功能对应一项关键技术。
> 关键技术不等同于功能本身，而是支撑该功能实现的最核心技术手段。
> 其它技术后期根据实现需要动态调整。

### 4.1 关键技术一：基于多任务框架的跨平台协同检测

**所属功能**：协同发现

**技术定位**：将协同检测定位为多任务问题，实现"是否协同"和"什么类型协同"的联合判定。

技术目标：
基于 2024 Coordination Detection Toolkit，构建多任务检测框架。

详细流程：

多行为协同边构建（五类边）
-> 候选协同对/群体发现
-> 任务一：协同判定（二分类：coordinated vs organic）
-> 任务二：协同类型分类（astroturfing / brigading / amplification / ...）

实现原则：

- 多任务框架统一处理检测与分类
- 显著性筛查使用统计检验方法
- 分类器可使用轻量模型或规则+统计方法
- 协调边必须可追溯、可解释

### 4.2 关键技术二：基于 LLM 增强的传播趋势预测

**所属功能**：传播监控

**技术定位**：以 LLM + 时序预测为核心，实现传播趋势的预判能力。

技术目标：
利用 LLM 的上下文理解能力增强时序预测模型，预测传播量、范围和速度的未来走势。

详细流程：

协同发现结果 + 传播数据输入
-> 时序特征提取
-> LLM 上下文增强（事件语义、历史模式）
-> 时序预测模型
-> 输出趋势预测结果

实现原则：

- LLM 用于增强时序预测（上下文理解 + 模式识别），不是替代统计方法
- 趋势预测是关键技术，用户画像/立场/危害性等是其它子功能的支撑技术
- 优先使用轻量方案，考虑 API 调用成本

### 4.3 关键技术三：基于 Agent+RAG 的攻击分析与报告生成

**所属功能**：报告研判

**技术定位**：通过 Agent 编排和 RAG 检索，显式消费协同发现和传播监控的结果，生成深度攻击分析报告。

技术目标：
构建 Agent+RAG 框架，整合多源上游证据，生成结构化、可审计的攻击分析报告。

详细流程：

KT1 协同发现结果 + KT2 传播监控结果
-> Agent 编排（多源证据整合）
-> RAG 检索（DISARM 知识库 + 历史案例 + 外部证据）
-> 攻击模式识别与分析
-> 结构化报告生成 + 处置建议

实现原则：

- Agent 是核心编排层，不是附属桥接
- RAG 提供领域知识增强
- 显式消费 KT1 和 KT2 的结构化输出是核心设计原则
- 报告必须可审计、可追溯

## 5. 文献与开源资源的使用口径

### 5.1 高水平文献池的使用方式

当前文献池应主要服务以下三条主线：

- 协同群体发现 / 同步行为检测
- 传播监控 / 角色识别 / 立场传播建模
- 事件 / claim / thread 报告研判与解释生成

文献不再按“bot 检测”“意图识别”“大模型总结”三块拆分，而要按系统主链路组织。

### 5.2 开源资源的定位

以下资源优先作为原型验证、数据组织参考、图构建组件或 benchmark 使用：

- coordination-network-toolkit
- CooRTweet
- TwiBot-20
- TwiBot-22
- BotDGT
- FakeNewsNet
- Hoaxy backend

定位原则：

- 不直接拼装成最终作品。
- 适合用于 baseline、bootstrapping、子模块验证与可视化参考。

当前 `开题报告.docx` 已经整体转向新框架，但仍有几处容易把评审理解带回旧骨架。建议优先修以下位置。

1. 作品名称统一替换为当前正式名称。
