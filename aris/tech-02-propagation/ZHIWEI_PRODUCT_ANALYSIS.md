## 三、WeiboReach 核心功能模块

### 3.1 模块 A：单条微博传播分析

**输入**：
- 微博 URL 或 mid

**分析维度**：
- 转发量、评论量、点赞量的时序曲线（分钟粒度）
- 传播路径图（谁转发了谁）
- 转发层级分布（一级/二级/三级传播占比）
- 关键传播节点识别（谁的转发引发了大量二次传播）

**输出**：
- 传播力指数（综合评分）
- 传播关键节点 Top N
- 转发路径可视化（树/图）

---

### 3.2 模块 B：传播路径与关键节点识别

**路径建模**：
- 基于微博原生转发关系的树状传播链
- 每一层传播节点的转发量与下游影响

**关键节点算法**（推测）：
- 度量：节点自身转发引发的下游传播量（子树大小）
- 综合评分：粉丝量 × 触达率 × 引发转发数
- 可能采用类似 PageRank / Betweenness 的图算法

**展示方式**：
- 节点大小 = 影响力
- 边权重 = 传播量
- 力导向布局（d3.js / ECharts）

---

### 3.3 模块 C：传播用户画像

**画像维度**：
- 转发者身份标签：媒体、KOL、蓝 V、普通用户、疑似水军
- 地域分布：省市级热力图
- 性别/年龄分布
- 活跃度分布
- 认证类型分布

**用途**：
- 分析事件是被哪类人群推高的
- 判断传播真实性（水军占比过高 → 异常信号）
- 评估传播影响力的质量（KOL 占比高 → 高价值传播）

---

### 3.4 模块 D：传播文本分析

**功能**：
- 转发/评论的情感倾向分布（正面/负面/中性）
- 高频词云
- 代表性评论抽取（高赞评论、争议评论）

**深度指标**：
- 观点极化度
- 立场分布（支持/反对/中立）
- 语义主题聚类

---

### 3.5 模块 E：传播力评估报告

**传播力指数**：0-100 综合评分

**组成要素**（推测）：
- **传播广度**：总触达用户数、独立转发用户数
- **传播深度**：最长传播链长度、平均传播层级
- **传播速度**：达到峰值传播量所需时间
- **传播持续性**：事件热度衰减半衰期

**对标基准**：
- 同类型事件的历史平均值
- 同行业事件的百分位
- 同作者历史微博的基线

## 四、知微事见：事件影响力产品

### 4.1 核心能力：事件影响力指数

**输入**：自然语言检索的热点事件名称或关键词

**算法推测**（基于公开资料与行业惯例）：
- **微博热度**：阅读量、讨论量、讨论用户数
- **媒体报道**：报道数量 × 媒体权威度加权
- **百度指数**：搜索热度
- **微信指数**：文章阅读与转发
- **综合模型**：多源加权 + 时间归一化

**输出**：事件影响力排名榜（日/周/月/年）

---

### 4.2 事件演化追踪

**时间轴视图**：事件从发酵到衰减的完整生命周期

**关键节点标注**：
- 爆发点（传播量突变）
- 转折点（官方回应、新证据出现）
- 衰退点（进入长尾期）
- 反复点（话题被重新提起）

**阶段划分**（行业惯例）：
1. **潜伏期** (Latency) ：事件发生但尚未被广泛讨论
2. **爆发期** (Burst) ：传播量快速增长
3. **蔓延期** (Spread) ：传播量高位震荡
4. **反复期** (Recurrence) ：衰退后被再次点燃
5. **衰退期** (Decline) ：话题彻底冷却

**对 Propagation Analysis 的关键启示**：
> 这正是我们 CascadeSwitch 的 4 体制（seeding → amplification → peak → decay）的产业对应。
> 产业界已验证阶段划分的必要性，我们的 regime 设定有产品对应。

---

### 4.3 事件分类与标签

| 层级 | 示例 |
|------|------|
| 一级分类 | 社会、娱乐、体育、政治、经济、科技、国际 |
| 二级标签 | 社会→刑事案件、食品安全、医疗、教育 |
| 情绪标签 | 正能量、负面事件、中性报道 |

**用途**：为事件影响力建模提供**类别先验**，不同类型事件有不同的传播规律。

## 五、实现方案推测（技术方案）

### 5.1 数据采集层

**数据源**：
- 微博开放 API + 爬虫（用于转发关系与历史数据）
- 微博热搜榜、微博实时广场
- 微信公众号、今日头条、新浪新闻等聚合
- 百度指数、微信指数（辅助热度评估）

**更新频率**：分钟级近实时

**存储**：
- 冷热分层（近期数据高可用、历史数据归档）
- 转发关系图可能使用图数据库（Neo4j / HugeGraph）
- 时序数据可能使用 InfluxDB / ClickHouse

---

### 5.2 事件识别层

**事件聚合**：
- 基于关键词/话题标签的文本聚类
- 基于时序突发检测（volume z-score）发现潜在事件
- 基于语义相似度合并同一事件的不同表述

**事件画像生成**：
- 事件类型分类（CNN/BERT 文本分类）
- 实体抽取（人物、地点、机构）
- 情绪分类（Sentiment Analysis）

---

### 5.3 传播分析层

**传播图构建**：
- 基于微博原生 repost_of 字段的转发树
- 基于时序 + 内容相似度补全隐式传播关系

**关键节点算法**：
- PageRank / Betweenness Centrality
- 自定义综合评分（粉丝数 × 触达率 × 下游量）

**传播力评估**：
- 多维度归一化 + 线性加权
- 可能带有学习参数（从历史数据回归）

---

### 5.4 影响力评分层

**事件影响力指数**（推测公式）：
```
影响力 = 微博热度 × 0.4
       + 媒体报道 × 0.3
       + 搜索指数 × 0.2
       + 持续时间 × 0.1
```
（权重为推测值，实际权重可能从专家标注回归学习）

**时间窗归一化**：避免历史事件长期累积优势

**校准**：基于专家标注的事件重要性，回归学习权重

---

### 5.5 可视化层

| 图表类型 | 用途 | 推测技术 |
|---------|------|----------|
| 传播路径图 | 展示转发链 | d3.js / ECharts force-directed layout |
| 时序曲线 | 多指标对比 | ECharts line chart |
| 词云 | 高频词展示 | wordcloud2.js |
| 桑基图 | 传播层级分布 | ECharts Sankey |
| 热力图 | 地域分布 | ECharts map + geo |

## 七、差异化定位：Propagation Analysis 相对知微的优势

### 7.1 知微的产品局限

- **商业产品的封闭性**：算法黑盒，不能用于学术发表
- **强依赖微博生态**：对平台原生字段高度耦合
- **缺乏预测能力**：以事后分析、影响力排名为主，前瞻预测能力弱
- **缺乏体制切换的显式建模**：阶段划分基于经验，而非可学习/可验证的模型
- **无公开学术成果**：没有发表的方法论可供参考

---

### 7.2 Propagation Analysis 的研究优势

- **CascadeSwitch 提供可发表的方法论**：显式 regime-switching + LLM 事件条件
- **跨平台泛化能力**：在 DeepHawkes Weibo + CasFlow Twitter 上验证
- **零训练、可解释**：W 矩阵、softmax 后验、参数化预测全部白盒
- **前瞻预测为核心**：区别于知微的事后分析
- **学术 + 工业双重价值**：既可发表论文，也可作为产品功能落地

---

### 7.3 对比矩阵

| 维度 | 知微产品 | Propagation Analysis 研究 |
|------|---------|----------|
| 时间取向 | 事后分析为主 | 前瞻预测为主 |
| 数据依赖 | 微博原生字段 | 仅用时序 + 图结构 |
| 算法透明度 | 黑盒商业指数 | 透明 W 矩阵 |
| 阶段划分 | 经验驱动 | 可学习/验证的 regime model |
| 评估方式 | 客户反馈 | 公开数据集基准 |
| 输出形式 | 商业报告 | 结构化 JSON + 论文 |

---

### 7.4 融合策略

在 CogGuard 系统集成时，可**借鉴知微的产品形态**：

| 知微形态 | CogGuard 借鉴 |

## 八、可操作的研究动作

基于知微分析，建议 Propagation Analysis 在现有 CascadeSwitch 基础上补充：

### 8.1 特征扩展（低成本）

在 `ts_features.py` 中新增：
- `max_chain_depth`：最长转发链深度
- `unique_reposter_count`：独立转发用户数
- `kol_ratio`：转发中 KOL 占比（利用 Coordination Discover coordination 信号）
- `time_to_peak`：观测窗口内是否已达到峰值
- `media_report_count`：媒体转载数（若数据可得）

---

### 8.2 输出扩展（中成本）

在 `trend_predictor.py` 的输出 JSON 中新增：
- `stage_transition_eta`：预期从当前体制转换到下一体制的小时数
- `peak_eta_hours`：预期达到峰值的小时数（若还未达峰）
- `similar_historical_events`：最相似的 3 个历史事件（需要事件库）
- `risk_level`：基于预测量的风险分级（低/中/高/极高）
- `influence_score`：类似知微传播力指数的 0-100 综合分

---

### 8.3 评估扩展（高价值）

在评估脚本中加入：
- **对比基准实验**：按知微事件分类（社会/娱乐/政治等）分别评估
- **用户画像敏感性**：在传播用户画像特征上做消融
- **阶段转换准确率**：验证 regime_posterior 预测的阶段转换是否与实际吻合
- **影响力排名相关性**：预测的影响力分数与实际传播量的 Spearman 相关

---

### 8.4 可视化扩展（展示价值）

参考知微产品的展示方式：
- 传播路径图（d3.js force-directed）
- 时序预测曲线 + 置信区间带
- 体制概率随时间变化的堆叠图
- 关键事件时间轴标注
- 传播用户画像饼图/热力图
