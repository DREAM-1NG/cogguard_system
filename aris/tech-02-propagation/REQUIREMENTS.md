# F-PROP（传播监控）功能级需求文档

> **所属功能**：传播监控（F-PROP / Propagation Analysis）  
> **主功能**：规模预测、角色定位、下一跳预测  
> **辅助能力**：传播时间线、证据链、范围估计、事件/内容/风险线索、前端可视化、Risk Review 结构化输出  
> **文档类型**：功能级需求与工程边界  
> **更新口径**：2026-06-23

---

## 1. 功能定位

F-PROP 是 CogGuard 主链路中的传播监控模块。它承接采集数据与 Coordination Discover 协同检测结果，围绕传播过程回答三个核心问题：

1. **规模预测**：事件未来会扩散到多大，传播方向是否上升、平稳或衰减。
2. **角色定位**：协同用户或关键节点在已观测传播图中扮演什么角色，证据是什么。
3. **下一跳预测**：在当前观测窗口结束时，下一批可能被激活的用户或传播边是什么。

其余能力均作为 auxiliary：传播子图、时间线、证据链、范围估计、影响力指数、立场/危害/情感线索、前端图表和 Risk Review 报告输入，可以增强解释与展示，但不作为三项主功能的完成前置条件。

---

## 2. 输入与输出边界

### 2.1 输入

- 观测窗口 `[0, t_obs]` 内的帖子、评论、转发、引用、时间戳和可用父子关系。
- Coordination Discover 输出的协同用户集合、协同群组、协同强度或网络密度。
- 可选事件元数据：关键词、平台、话题、时间窗、已知外部事件。
- 可选内容线索：文本、情感、立场、危害标签等，只作为辅助输入。

### 2.2 输出

| 主功能 | 输出示例 | 说明 |
|---|---|---|
| 规模预测 | `predicted_size`、`direction`、`confidence`、`horizon` | 可先输出点估计，再逐步补不确定性 |
| 角色定位 | `role_labels`、`role_evidence`、`key_users` | 角色必须有图结构或行为证据 |
| 下一跳预测 | `candidate_users`、`candidate_edges`、`ranked_next_hops` | 必须说明候选集来源，避免未来泄漏 |
| 辅助输出 | timeline、evidence_chains、scope、risk_hint、explanation | 服务展示和报告，不替代主功能 |

输出结构可以随实现演进，不在本文档中固定具体字段名和接口路径；但每次变更应同步说明前端和 Risk Review 的消费方式。

## 3. 三项主功能需求

### 3.1 规模预测

目标：给定早期观测窗口，预测未来传播规模、走势和可选置信度。

最低要求：

- 明确 `t_obs`、预测 horizon 和目标标签。
- 至少保留一个简单 baseline，例如 naive / EWMA / RandomForestRegressor。
- 报告至少一种规模误差指标和一种方向指标。
- 方法不限，可使用 CascadeSwitch、传统回归、点过程、图模型、多尺度扩散模型或组合方案。

### 3.2 角色定位

目标：对已观测传播图中的协同用户和关键节点进行角色识别，并给出证据。

最低要求：

- 能按 Coordination Discover 协同用户集合过滤或高亮传播图。
- 至少识别起爆、桥接、扩散/放大等基础角色。
- 每个角色标签应有可追溯依据，例如出入度、介数中心性、路径位置、传播时间或支撑帖子。
- 允许先用启发式规则实现，再逐步替换为学习模型。

### 3.3 下一跳预测

目标：在不使用未来真实节点或真实边的前提下，预测未来窗口内可能被激活的用户或传播边。

最低要求：

- 明确候选用户或候选边如何在 `t_obs` 时刻获得。
- 不使用 future child、真实 parent 或未来传播边构造输入。
- 同时报告候选覆盖和排序质量，不能只报告全局 AUC。
- 方法不限，可使用逻辑回归、学习排序、Topo-LSTM、TGN、FOREST、MINDS、HyperIDP、DyGLib 等。

## 4. 辅助能力定位

| 辅助能力 | 定位 |
|---|---|
| 传播时间线 | 支撑规模预测解释和前端展示 |
| 证据链 / 关键路径回溯 | 支撑角色定位和报告研判，只解释已发生传播 |
| 范围估计 | 可作为规模预测或态势展示的补充 |
| 立场 / 危害 / 情感线索 | 可作为 Risk Review 或内容分析辅助输入，不作为 Propagation Analysis 主功能 |
| 影响力指数 | 可作为综合展示指标，不替代规模预测或角色定位 |
| 前端可视化 | 展示已落地能力，不提前展示未完成预测为已完成 |

## 5. 方法与文献参考

本文档不指定唯一模型。可选方法池包括：

- 规模预测：DeepCas、DeepHawkes、CasFlow、CasDO、ConCat、CasFT、CasTemp、CascadeSwitch。
- 多尺度扩散：FOREST、MINDS、HyperIDP。
- 下一跳预测：Topo-LSTM、DeepInf、TGAT、TGN、CAW、DyGFormer、TGSL、TNCN、TAMI。
- 角色定位与证据：中心性、PageRank、结构洞、Provenance for Online Information Diffusion、Bi-GCN。

选择方法时，应在提交说明中解释：

- 覆盖哪一项主功能。
- 需要哪些数据字段。
- 如何避免未来泄漏。
- 相比已有 baseline 的收益或不足。

## 6. 工程边界

允许修改：

- 后端传播监控核心逻辑、服务层、API 和测试。
- 前端传播监控页面中与已落地能力相关的展示。
- 本目录下稳定 Markdown 文档。

默认不修改：

- Coordination Discover 协同检测内部逻辑。
- Risk Review 报告研判内部逻辑。
- 数据采集器和爬虫基础设施。

接口设计原则：

- 可以先使用最小结构化输出，不强制一次性固定最终 API。
- 新增字段必须能解释其服务哪一项主功能或 auxiliary。
- 前端不得把实验性或未落地能力展示为已完成。

---

## 7. 最低交付物

| 交付物 | 要求 |
|---|---|
| 功能定位说明 | 明确本次工作覆盖规模预测、角色定位、下一跳预测中的哪几项 |
| 数据适配报告 | 说明数据是否包含时间戳、父子边、用户 ID、协同用户集合和最终规模标签 |
| 评估协议 | 说明观测窗口、预测窗口、候选集构造和无未来泄漏策略 |
| baseline 对比 | 至少与当前已有 baseline 或简单启发式对比 |
| 工程输出 | 提供可被服务层、前端或 Risk Review 消费的结构化结果 |

---

## 8. 非目标

- 不要求一次性完成所有辅助能力。
- 不要求固定最终模型。
- 不要求所有论文完整复现。
- 不要求为了展示而虚构未完成的预测结果。
